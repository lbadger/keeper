# Keeper v1.0.1

This patch release adds independent full file backups on an existing tape and
includes two fixes for inspection and tape initialization.

## Changes

- `backup --append-after ID` appends a full tar backup after the last completed
  backup on its final cartridge. It uses the existing append validation and
  positioning, preserves earlier backups, and starts a fresh tar snapshot so
  unchanged files are included. The new backup restores using its own ID alone
  and can become the base for later incrementals. Local and SSH sources, changed
  exclusions, previews, and read-back verification are supported.
- Inspection now says whether data checksums were checked during the current
  operation. It does not imply that an earlier `backup --verify` was skipped;
  verification history is not stored on tape.
- At the initial blank-cartridge prompt of a fresh full backup, an explicitly
  confirmed wipe can initialize media whose short records prevent Keeper from
  reading its old contents. Append and continuation protection remain in place.

```bash
./keeper backup --source /srv/data --append-after LAST_BACKUP_ID --verify
```

Load the specified backup's final cartridge. The ID must identify its last
completed backup, and the recorded tail must be clean. `--append-after` requires
the full level and cannot be combined with `--base` or `--append`.

## Download and compatibility

Download `keeper` and `keeper.sha256`, then run:

```bash
sha256sum --check keeper.sha256
chmod +x keeper
./keeper --version
```

The executable targets Linux x86-64 with glibc 2.31 or newer and zlib, with Python
bundled. GNU tar and `mt-st` remain host requirements for file archives and tape
operations. SSH and ZFS workflows require their corresponding host tools.

Tape formats, restore markers, and the SSH source protocol are unchanged from
v1.0.0. Existing backups remain readable.

Automated validation covers independent restores, preservation of earlier tape
records, rollover, stale and incomplete tails, filename indexes, local and SSH
sources, and the standalone executable. Physical-drive qualification remains
separate from file-backed media and simulator testing.

[reference guide](https://github.com/lbadger/keeper/blob/v1.0.1/docs/reference.md).

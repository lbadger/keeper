# Keeper v1.0.0

Keeper streams files, existing ZFS snapshots, and arbitrary byte streams to
Linux tape drives, and restores them with checksum and completion checks.
This is the first release under the Keeper name and version sequence.

## Included

- Full and incremental file backups, automatic appending, multi-cartridge
  rollover, SSH sources, and source-relative exclusions.
- Native ZFS full/incremental sends and receives, encrypted raw sends, and
  `--append-after ID` for an independent full snapshot on an existing tape.
- Managed producer/stdin backups and exact-byte stream restores.
- Per-backup verification, indexed tar filename listings, cartridge labels,
  optional inventories, and restore-chain planning.
- Drive status, compression controls, rewind, eject, and confirmed tape erasure.
- Live terminal progress, diagnostic logs, and ASCII branding.
- A concise README and a file-backed example covering backup, verification,
  restore planning, incremental recovery, and byte-stream recovery.

## Download

Download `keeper` and `keeper.sha256`, then run:

```bash
sha256sum --check keeper.sha256
chmod +x keeper
./keeper --version
./keeper --help
```

The executable targets Linux x86-64 with glibc 2.31 or newer and zlib. Python
is bundled; this is not a fully statically linked binary. GNU tar and `mt-st`
are host tools for file archives and physical tape operations. SSH and native
ZFS workflows require OpenSSH/OpenZFS on the relevant machines.

## Compatibility and validation

Tape formats 3 (tar), 4 (ZFS), and 5 (byte streams) remain compatible with the
previous tape-backup application. Existing restore markers and shared lock names
are retained. The default remote helper name is `keeper`; an explicit
`--remote-program` can select an older compatible helper.

Validation covers the source, standalone binary, real GNU tar and SSH,
file-backed cartridges, the tape simulator, an archived legacy tape fixture,
and a Debian 11 runtime without installed Python. Native ZFS scratch-pool tests
and physical-drive qualification are separate from simulated-media coverage.

See the [README](https://github.com/lbadger/keeper/blob/v1.0.0/README.md) and
[reference guide](https://github.com/lbadger/keeper/blob/v1.0.0/docs/reference.md).
